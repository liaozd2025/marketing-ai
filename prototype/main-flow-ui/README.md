# PROTOTYPE — 主流程界面对比稿（丢弃品）

> 一次性原型，回答一个设计问题后即弃。**不要**把这里的代码当实现起点。
>
> **✅ 结论（2026-07-29）：选定 `C` 混合式**（工作台骨架 + 一键生成 + 每条聊着改），
> 并吸收 B 的「可发布状态汇总条」+「可展开的完善度实体列表」。
> 全文见 `docs/research/2026-07-29-ui-prototype-conclusions.md`，落点 GitHub #5。

**问题**：商家从进入平台到拿到一条「可发布」内容的主流程界面应该长什么样？

**三个变体**（`?variant=` 或 `#` 切换，底部浮动条 / ← → 键盘切换）：

- `A` 对话式 — 跟智能体聊天出内容，知识库在幕后
- `B` 工作台式 — 知识库 → 选 Skill → 参数 → 生成 → 预览，结构化仪表盘
- `C` 混合式 — 工作台骨架 + 一键生成 + 结果上「聊着改」

**运行**：

```sh
open prototype/main-flow-ui/index.html            # 三范式对比稿（范式决策用）
open prototype/main-flow-ui/main-flow-c-shell.html # 选定 C 精修稿：JustAI 应用外壳 + C 混合式
```

`main-flow-c-shell.html` 是定稿 C 的视觉精修，按 JustAI 小加同学 外壳（常驻左侧导航 +
极简白 + 黑色按钮 + 细线图标 + 紫色点缀），导航项换成本平台领域。含三块可点界面：

- **新建内容**：JustAI「新对话」式 hero，对话框内可勾选「我的资料」内容 → 提交落地 C 工作台
  （可发布汇总条 + 结果卡片 + 每条聊着改）。`?autogen=1` 直达已生成状态。
- **我的资料**（= 知识库 UI 标签）：借 JustAI 录入交互（上传文件 / 加链接），但产物是六类
  **结构化实体**（品牌档案/Offering/客群/活动/会员分层/素材），不是扁平文档——守 ADR-0001。

全静态假数据（虚构商家「悦见美学·皮肤管理工作室」），无后端。四条判断标准
（上手门槛 / 批量效率 / 知识库信任感 / 违禁词与可发布状态）在每个变体里均有对应交互，逐一点着比。

结论回写 `docs/research/2026-07-29-ui-prototype-conclusions.md`，原型代码最终归档到 throwaway 分支。
