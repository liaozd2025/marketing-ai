# ADR-0001: 垂类适配用「核心实体 + 垂类包配置」，不用独立 schema 或全可配置实体引擎

日期：2026-07-29 · 状态：已接受

## 背景

平台要同时服务美业/大健康与电商/品牌零售两个垂类，两者的知识库内容差异大（服务项目/卡项 vs SKU/卖点），且未来可能扩展更多垂类。备选方案：每垂类独立表结构（零复用）、EAV 全可配置实体引擎（MVP 过度设计）、固定核心实体 + 垂类配置。

## 决策

六个固定核心实体：品牌档案、Offering（可售卖物统一抽象）、素材、客群、活动、会员分层。垂类差异全部收敛进**垂类包**配置：Offering 字段模板、场景词表、违禁词表、Skill 预设。

## 后果

- 加新垂类 = 加一份垂类包配置，不做数据库迁移。
- Offering 抽象必须同时容纳美业与电商：Phase 1 内用电商字段模板做纸面试填校验。
- 垂类包是配置数据而非代码分支——Skill 实现不得出现 `if (vertical === 'beauty')` 式硬编码。
