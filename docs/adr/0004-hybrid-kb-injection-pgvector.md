# ADR-0004: 知识库消费用混合模式——核心实体结构化全量注入 + 素材/历史内容向量检索

日期：2026-07-29 · 状态：已接受

## 背景

单商家知识库的结构化实体规模小（数千 token 内），全量注入 prompt 即可；但素材（图片语义检索）和未来累积的历史内容属于检索型数据，标签筛选的表达力有限。

## 决策

- 品牌档案、Offering、客群、活动、会员分层：生成时**结构化全量注入**。
- 素材、历史内容：**向量检索**（多模态 embedding，国内可用通义系），落在 PostgreSQL 的 pgvector 上，不引入独立向量库。

## 后果

- 一个 Postgres 同时承载多租户结构化数据与向量索引，运维面最小。
- 素材需要 embedding 流水线（上传时向量化）；检索按租户隔离。
- 若某商家实体规模超出注入预算，再局部引入检索，属实现细节不需重开 ADR。
