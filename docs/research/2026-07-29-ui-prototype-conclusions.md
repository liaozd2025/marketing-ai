# 主流程界面范式结论：选定「混合式（工作台骨架 + 聊着改）」

> 日期：2026-07-29 · 方法：`/prototype` 可点击对比稿（对话式 / 工作台式 / 混合式三稿）· 决策人：产品负责人
> 原型代码（丢弃品）：`prototype/main-flow-ui/index.html`，`?variant=A|B|C&autogen=1` 可看各范式已生成状态。**勿作实现起点。**

## 回答的设计问题

商家从进入平台到拿到一条「可发布」朋友圈内容的**主流程界面**应该长什么样？争论点是交互范式：**对话式（A）vs 工作台式（B）vs 混合式（C）**。

## 结论

**选定 C 混合式**：以「工作台骨架 + 一键生成」为主路径，生成结果上**每条独立「聊着改」**做局部对话微调；顶部常驻**「本次参考的知识库上下文」**chips（可增减）。

并吸收 B 的两个零件，作为落地时的补充要求：

1. **生成结果上方加一行可发布状态汇总条**——「共 N 条 · X 可发布 · Y 待改」，解决日更前"快速确认哪些能发"。
2. **顶部 KB 上下文 chips 可展开成带完善度的实体列表**（B 左栏那种），给想深入核对的商家；默认收起保持轻量。

即 skill 所说的「C 的骨架 + B 的汇总/实体面板」混搭。

## 为什么不是 A / B（决策依据）

差异化定位是**私域深度运营**，而私域的刚需正是**品牌人设/话术的信任感**——商家要能感到"内容出自我的资料"。这决定了「知识库可见性」（标准③）不能弱。A 恰恰把知识库藏在幕后（这是 JustAI 的做法），方向上就是我们要区别于竞品的地方，因此排除。B 信任感与批量总览最强，但纯工作台对"非运营专业的美业老板娘"门槛偏高、表单易劝退。C 在三项标准上同时拿高分，唯一缺口（无全局可发布汇总）用 B 的零件补齐即可。

## 逐条回应四项判断标准

| 判断标准 | A 对话式 | B 工作台式 | **C 混合式（选定）** |
|---|---|---|---|
| ① 老板娘上手门槛 | 最低（像发微信），但有"空白输入框恐惧" | 最高（须理解 Skill/参数概念，表单易劝退） | **偏低**：主路径只有一个「一键生成」，所有配置可跳过；想调再调 |
| ② 日更批量效率（一次 3–5 条 + 选图） | 一句话出多条✓，但改某条须在对话里绕，线性易乱 | 数量+类型批量最强，grid 一屏挑能发的 | **一键出 3 条✓ + 每条独立「聊着改」互不干扰**，批量与精修兼得 |
| ③ 知识库可见性/信任感 | 最弱：库在幕后，仅生成后来源 chips | 最强：左栏常驻实体+完善度 | 强：顶部常驻上下文 chips、可增减、"生成有据可循"；可展开成实体列表补齐到 B 的水平 |
| ④ 违禁词/可发布状态呈现（验收标准 3） | 卡片呈现一致，但违规卡混在对话流中**易被划走漏看** | 最好：顶部有可发布汇总条 | 卡头状态清晰；**落地须补一行汇总条**追平 B |

标准④的卡片级交互三稿一致，作为**所有范式的既定要求**固化下来：
- 违禁词**波浪线高亮** + 卡头「不可发布 · N 处违规」红 badge；
- lint 条**列出命中词**并标注类别（美业·疗效承诺类），明示"已阻止「可发布」"；
- 「一键合规改写」把文案替换为合规版并**翻绿为「可发布」**；
- 过校验内容显示「✓ 已过校验，可复制发布」。
- 效果类图配图建议强制标注「实拍」（呼应 ADR-0002），模板合成图标注「合成」。

## 视觉方向（2026-07-29 追加）

范式定稿后，产品负责人指定**视觉外壳按 JustAI 小加同学**：常驻左侧导航 + 极简白底 + 黑色主按钮 + 细线图标 + 紫色点缀。导航项换成本平台领域（**新建内容 / Skill 技能 / 我的资料 / 内容库**——最终为二库制且知识库 UI 标签为「我的资料」，见下文「库的划分」「命名与录入形态」两节），平台品牌在左上、租户（商家）在左下角——与竞品同构。精修稿：`prototype/main-flow-ui/main-flow-c-shell.html`。

落地要点：主按钮用近黑色（非品牌玫瑰金），品牌暖色调只在内容/租户标识处点缀；知识库上下文与完善度面板沿用该极简风格。

## 入口形态（2026-07-30 追加）：新建内容 = 对话式 hero，对话框内选知识库

「新建内容」入口采用 JustAI「新对话」式的**居中 hero 大输入框**，关键差异化在于**对话框内可直接勾选知识库内容**：composer 顶部常驻「已选知识库」chips，点「选知识库内容」弹出六实体多选器（品牌档案/Offering/客群/活动/会员分层/素材）。这把知识库的可见性与可控性前置到创作入口，正面服务标准③（信任感）——商家在生成前就看得见、选得动"内容出自哪些资料"。

流程：hero 选知识库 + 输入意图 + 选 Skill → 提交 → 落地 C 混合式工作台（可发布汇总条 + 结果卡片 + 每条聊着改）。即**入口对话式、结果工作台式**，与 C 的定位一致。hero 下方放 Skill 卡片（四个）与「最近生成」预览。

## 库的划分（2026-07-30 追加）：三库砍成二库

澄清「知识库 / 素材库 / 内容库」的关系——三者是内容流水线的**输入 / 配图源 / 输出**三个阶段，原理不重复；但有两处真重复：

1. **素材 ⊂ 知识库**：CONTEXT.md 已把「素材」定义为知识库六实体之一，素材库不应与知识库并列 → **收进知识库**（做成 tab / section）。
2. **内容库 vs 侧栏「最近生成」**：二者都装成品 → 内容库 = 全量可检索归档，最近生成 = 快捷入口，明确分工（而非内容库与知识库重复）。

**内容库不与知识库重复**：知识库是事实输入，内容库是成品输出，且成品按 ADR-0004 回流为风格参考。

**结论：导航采用二库制** —— **知识库（含素材）** + **内容库（成品归档）**。是否在 Phase 1 就独立「内容库」浏览面可延后（MVP 用「最近生成」列表可能已够）。此划分供 #3（知识库实体范围）与后续内容归档设计参考。

## 命名与录入形态（2026-07-30 追加）：UI 标签「我的资料」，录入借 JustAI、产出仍是结构化实体

**命名分层**：面向商家的 **UI 标签用「我的资料」**（更亲切、贴 JustAI）；**领域/架构术语仍用「知识库」**（CONTEXT.md 的 ubiquitous language，并提醒别在架构里用「资料库」）。二者是标签 vs 术语的分工，不冲突。

**关键红线**：JustAI 的「我的资料」本质是**文件夹装文档**（传 PDF/链接、AI 去读）的扁平 RAG 模型；直接照搬会**悄悄推翻 ADR-0001**（结构化六实体 + 垂类包才是差异化根）。因此只借它的**视觉与录入交互**，不借它的数据模型：

- 「我的资料」列表 = 六类**结构化资料卡**（品牌档案/Offering/客群/活动/会员分层/素材）+ 完善度，非任意文件夹。
- 每类详情页放 JustAI 式**上传文件 / 添加链接**区（= PRD「冷启动：AI 抽取预填」入口），但产物是**结构化字段**（品牌档案→人设/语气/品牌故事/禁忌；Offering→卡项列表；素材→打标图库），而非留一堆散文档。
- 即「**借 JustAI 的 ingestion UX，守 ADR-0001 的结构化知识库**」。

**若真要改成扁平文档模型**：那是推翻 ADR-0001 的大改，需显式决策并回写 ADR，不在本次范围。
