# JustAI（justailab.com）深度功能分析

> 调研日期：2026-07-29 · 用途：为自建「私域内容营销平台」提供竞品拆解与架构参考

## 一、产品概览

- **产品名**：JustAI 文案助手，核心智能体叫「小加同学」
- **定位**：中小商家 AI 内容营销平台 —— "一句话生成图文笔记、公众号文章、营销方案与 AI 封面配图"
- **公司**：深圳团队，聚焦本地生活与实体行业，主张覆盖"内容生产 → 种草分发 → 数据分析"全链路
- **目标用户**：餐饮、美业、酒店、文旅、零售等**没有专职运营团队**的中小商家；也覆盖内容创作者、品牌运营、工厂 OEM/ODM
- **产品形态**：Web 应用（justailab.com）+ 微信小程序（笔记复刻）+ 开放平台（Skill 分发进第三方 Agent 工具）

## 二、产品架构：Agent + Skill + 知识库 三层

这正是「智能体 + Skill 技能 + 知识库」的垂类落地样本：

```
用户一句话需求
      │
      ▼
┌─────────────────────────────┐
│  智能体「小加同学」(对话式入口)      │  ← 意图识别、任务编排、会话续聊
├─────────────────────────────┤
│  Skill 技能库 (10+ 垂类技能)       │  ← 每个技能 = 一条固化的垂类生产链路
│  · 小红书图文笔记 / 爆款复刻          │
│  · 公众号长文                       │
│  · 营销方案全案 / 内容排期日历        │
│  · 大众点评运营方案 / 美团推广文案     │
│  · PPT / AI 封面配图                │
│  · 风格类: Q版漫画、Plog封面、手账拼贴 │
├─────────────────────────────┤
│  知识库 / 资料库 (project)          │  ← 门店照片、产品卖点、核心话术、
│                                    │    历史内容；保证品牌风格长期统一
└─────────────────────────────┘
      │
      ▼
多平台交付: 小红书 / 公众号 / 抖音 / 大众点评 / 美团 / 知乎 / 朋友圈
```

## 三、功能模块拆解

### 1. 智能体「小加同学」（主产品）

- 对话式入口，一句话生成完整营销物料（文案 + 配图一起交付，"拿来即发"）
- 官方引导的输入公式：**场景 + 产品 + 目标 + 偏好**
- 支持**对话式微调**：在同一会话上持续改写、扩展（conversation 续聊）
- 产出物：图文笔记、公众号长文、营销全案（活动主题/目标人群/推广节奏）、PPT、封面图

### 2. Skill 技能库

- 10+ 垂类技能，两类：
  - **平台运营型**：大众点评装修专家、美团推广文案、小红书 IP 架构师、公众号长文
  - **风格模板型**：Q 版漫画图文、Plog 博主封面、百万博主同款封面、健康养生卡片、旅行攻略手账拼贴
- 技能可通过 API 管理（创建/更新/删除/上传缩略图），说明技能体系是**平台化、可扩展的**，不是硬编码

### 3. 知识库 / 资料库

- 存储：门店照片、产品卖点、核心话术、品牌素材、历史内容
- 生成时通过 `project-id` 关联，实现"参考资料驱动创作"（内容有据可循 + 品牌风格统一）
- 这是他们对抗"AI 内容千篇一律"的核心机制

### 4. 营销码 / 种草码（增长引擎，最有特色的模块）

- **商家端**：创建二维码，预设店铺信息
- **顾客端**：扫码 → AI 根据预设信息生成优质评价 → 一键发布到大众点评/美团/小红书/抖音/知乎/朋友圈
- 本质是「**AI 辅助 UGC 裂变**」：让每位顾客成为推广大使，商家低成本获取真实账号发布的内容
- 支撑"1 天 100+ 条图文"的关键之一（固定排期 + 素材库复用 + 顾客 UGC 三步）

### 5. 商家工具（免费获客型工具）

- 营销 ROI 计算器（CAC / LTV / ROI）
- 餐饮开店成本计算器（盈亏平衡点、日均客流）
- 典型的 SEO/获客漏斗打法：免费工具引流 → 转化到主产品

### 6. 开放平台（架构上最值得借鉴的部分）

把「小加同学」的能力封装成 **Agent Skill 分发到第三方 AI 工具**里：

- 支持 Trae、通义灵码、CodeBuddy、Kimi、Claude Code、Cursor 等
- 安装方式："复制一段指令即可接入"，即让用户的 Agent 自动安装 GitHub 上的 skill 仓库
- 公开仓库：[qinshimeng18/xiaojia-skills](https://github.com/qinshimeng18/xiaojia-skills)（skill 名 `xiaojia-Marketing-Delivery`）

**SKILL.md 揭示的协议设计**（对自建平台最有参考价值）：

| 设计点 | 实现 |
|---|---|
| 鉴权 | 环境变量 `JUSTAI_OPENAPI_API_KEY`，登录后自动创建，用户零配置 |
| 任务提交 | `chat.py --message`，可选 `--project-id`（挂知识库）`--skill-id`（走特定技能链路） |
| 异步轮询 | 返回 `conversation_id`，用 `chat_result.py` 轮询 `status`；图片类慢任务建议 ≥300s 超时 |
| 会话续聊 | 复用 `conversation_id` 在已有方案上迭代 |
| 结果结构 | `branch`（实际执行分支）+ `result`（结构化）+ `text`（兜底）+ `web_url`（网页预览链接） |
| 交付规则 | 图文必须同时含标题/正文/图片链接/web_url，缺 web_url 视为不合格 |
| 触发设计 | 显式（提到"小加"）+ 隐式（任何营销类请求关键词） |
| 其他接口 | `/openapi/images/upload`、`/openapi/skills/*`（技能 CRUD） |

### 7. 技术栈线索

- 自称 "JustAI 2.0 文案模型"，基于 DeepSeek、Azure（OpenAI）等大模型之上做营销垂类调优/工程化
- 多模型降级机制（fallback）
- 异步任务 + 轮询架构，前端有 agent 会话预览页（`/pages/agent/preview?conversation_id=`）

## 四、商业模式

- 免费注册额度体验全部核心功能 → 高频用户订阅套餐
- 免费商家工具做获客漏斗
- 开放平台按 API 额度/订阅收费
- 营销码面向门店场景（可能按店/按码收费）

## 五、对自建「私域内容营销平台」的启示

1. **护城河不在生成，在垂类链路**：JustAI 的价值 = 把"平台爆单逻辑"（点评装修、小红书种草结构）固化成 Skill，而不是通用写作。自建时每个 Skill 应该编码一条**可验证的垂类方法论**。
2. **知识库是风格一致性的解**：project/资料库机制让内容"有据可循"，这是私域场景（品牌人设、话术体系）更刚需的能力。
3. **先 Skill 后平台是可行路径**：JustAI 反向证明了 Agent+Skill 形态可以先于 Web 平台存在——他们甚至把 skill 分发到别人的 Agent 里当获客渠道。
4. **差异化空间——私域**：JustAI 重心在**公域种草**（小红书/点评/美团获客）。私域（公众号深度运营、朋友圈、社群、企微 SOP、会员触达）的内容营销链路他们只是浅覆盖，这是明确的差异化切口。
5. **交付标准值得抄**：他们对"合格产出"的定义（结构化结果 + 图片 + 可分享 web_url）是产品化的关键细节。

## 附：首轮需求决策（2026-07-29，与产品负责人确认）

| 决策项 | 结论 |
|---|---|
| 目标用户 | 特定垂类商家：**美业/大健康 + 电商/品牌零售**（双垂类） |
| 私域渠道 | 全渠道：微信公众号、朋友圈+社群/企微、小红书/视频号种草、会员/客户生命周期触达 |
| 技术路线 | **直接做 Web 平台**（不走"先本地 Skill 后平台"路径） |
| MVP 链路 | **知识库 → 内容生成**（发布环节先手动） |
| 模型选型 | 多模型路由 + 降级（国内模型为主力，provider 抽象层可切换） |
| 租户形态 | 多租户架构从第一天设计，MVP 只开放 1-3 个种子商家内测 |

**双垂类带来的架构约束**：美业（到店服务 + 会员复购）和电商（SKU + 卖点）的知识库结构差异大，Skill 体系和知识库 schema 必须从第一天设计成**可插拔的垂类包**（vertical pack），而不是硬编码单一行业。
